# ORP to Existing Ontologies Mapping

**Sprint:** 1.7.4
**Created:** 2026-04-08
**Purpose:** Research existing semantic web ontologies to identify reusable terms for ORP JSON-LD schema

---

## Executive Summary

This document maps OpenReason Protocol (ORP) concepts to existing W3C and community-standard ontologies. By reusing established terms, we ensure:
- **Interoperability** with existing semantic web tools
- **Reduced complexity** (don't reinvent the wheel)
- **Ecosystem integration** (PROV, DCAT, linked data platforms)

**Key Finding:** ~60% of ORP metadata can use existing ontology terms. Core ORP-specific concepts (layers, compliance levels, fork relationships) require custom vocabulary.

---

## 1. W3C PROV-O (Provenance Ontology)

**URL:** https://www.w3.org/TR/prov-o/
**Version:** W3C Recommendation (2013)
**Purpose:** Model provenance information for entities, activities, and agents

### Core Classes

| PROV-O Class | Definition | ORP Relevance |
|--------------|------------|---------------|
| `prov:Entity` | Physical, digital, conceptual thing | **ORP Document**, **Dataset** (Layer 1) |
| `prov:Activity` | Something that occurs over time | **Decision** (Layer 4), **Analysis** (Layer 2) |
| `prov:Agent` | Something that bears responsibility | **Author**, **Decision-maker**, **Analyst** |

### Key Properties

| Property | Domain → Range | ORP Use Case |
|----------|----------------|--------------|
| `prov:wasGeneratedBy` | Entity → Activity | Document generated by policy analysis activity |
| `prov:wasAttributedTo` | Entity → Agent | Dataset attributed to collecting organization |
| `prov:wasDerivedFrom` | Entity → Entity | **Fork relationship** (Layer 5) |
| `prov:used` | Activity → Entity | Decision used specific dataset |
| `prov:wasAssociatedWith` | Activity → Agent | Analysis associated with specific analyst |
| `prov:hadPrimarySource` | Entity → Entity | Dataset has primary source (original data) |
| `prov:generatedAtTime` | Entity → xsd:dateTime | Dataset creation timestamp |
| `prov:wasInvalidatedAt` | Entity → xsd:dateTime | Dataset deprecated/superseded |

### ORP Mapping: Layer 1 (Data Provenance)

```turtle
# Example: Danish property valuations dataset
:danish-valuations-2023 a prov:Entity, dcat:Dataset ;
    prov:wasAttributedTo :danish-tax-authority ;
    prov:wasGeneratedBy :valuation-process-2023 ;
    prov:hadPrimarySource :cadastral-records ;
    prov:generatedAtTime "2023-06-15"^^xsd:date .

:danish-tax-authority a prov:Agent, schema:Organization ;
    schema:name "Danish Tax Authority" .
```

### ORP Mapping: Layer 4 (Accountability Ledger)

```turtle
# Example: Decision to exclude non-residential properties
:decision-001 a prov:Activity, orp:Decision ;
    prov:wasAssociatedWith :asbjorn-ras ;
    prov:used :danish-valuations-2023 ;
    prov:startedAtTime "2024-01-15T14:30:00"^^xsd:dateTime ;
    prov:endedAtTime "2024-01-15T14:30:00"^^xsd:dateTime ;
    dc:description "Excluded non-residential properties from simulation" .
```

### ORP Mapping: Layer 5 (Fork Registry)

```turtle
# Example: Alternative proposal forked from original
:dk-property-tax-alternative-2024 a orp:Document, prov:Entity ;
    prov:wasDerivedFrom :dk-property-tax-reform-2024 ;
    orp:forkType "critique" ;
    dc:description "Alternative using different valuation methodology" .
```

**Reusable PROV-O Terms for ORP:**
- ✅ `prov:Entity` (ORP documents, datasets)
- ✅ `prov:Activity` (decisions, analyses)
- ✅ `prov:Agent` (authors, decision-makers)
- ✅ `prov:wasGeneratedBy`, `prov:wasAttributedTo`, `prov:wasDerivedFrom`
- ✅ `prov:generatedAtTime` (timestamps)

**ORP-Specific Extensions Needed:**
- `orp:Decision` (subclass of `prov:Activity`) with constitutive logic field
- `orp:forkType` property (critique, alternative, amendment, response)
- `orp:accountabilityGap` property (for post-hoc reconstructions)

## 2. DCAT (Data Catalog Vocabulary)

**URL:** https://www.w3.org/TR/vocab-dcat-2/
**Version:** DCAT 2.0 (W3C Recommendation, 2020)
**Purpose:** Describe datasets in data catalogs

### Core Classes

| DCAT Class | Definition | ORP Relevance |
|------------|------------|---------------|
| `dcat:Dataset` | Collection of data | **Dataset** (Layer 1) |
| `dcat:Distribution` | Specific representation of dataset | Dataset file formats (CSV, Parquet, etc.) |
| `dcat:CatalogRecord` | Metadata about dataset entry | ORP document as catalog record |
| `dcat:DataService` | Service providing access to datasets | Future: ORP REST API as data service |

### Key Properties

| Property | Domain → Range | ORP Use Case |
|----------|----------------|--------------|
| `dcat:keyword` | Dataset → Literal | Dataset tags/categorization |
| `dcat:theme` | Dataset → Concept | Policy domain (taxation, healthcare, etc.) |
| `dcat:temporalCoverage` | Dataset → PeriodOfTime | Time period dataset covers |
| `dcat:spatialCoverage` | Dataset → Location | Geographic coverage |
| `dcat:contactPoint` | Dataset → Contact | Dataset steward contact info |
| `dcat:distribution` | Dataset → Distribution | CSV, JSON, Parquet versions |
| `dcat:landingPage` | Dataset → Document | Documentation URL |
| `dcat:qualityAnnotation` | Resource → Annotation | **Data quality notes** (Layer 1) |

### ORP Mapping: Layer 1 Dataset

```turtle
:danish-valuations-2023 a dcat:Dataset, prov:Entity ;
    dc:title "Danish Property Valuations 2023" ;
    dc:description "Public property tax valuations for all Danish residential properties" ;
    dcat:keyword "property tax", "denmark", "valuations" ;
    dcat:theme <http://eurovoc.europa.eu/2188> ;  # Taxation
    dcat:temporalCoverage [
        a dcterms:PeriodOfTime ;
        dcat:startDate "2023-01-01"^^xsd:date ;
        dcat:endDate "2023-12-31"^^xsd:date
    ] ;
    dcat:spatialCoverage [
        a dc:Location ;
        locn:geometry "POLYGON((8.0 54.5, 15.2 54.5, 15.2 57.8, 8.0 57.8, 8.0 54.5))"^^gsp:wktLiteral
    ] ;
    dcat:distribution [
        a dcat:Distribution ;
        dcat:downloadURL <https://data.skat.dk/valuations-2023.csv> ;
        dcat:mediaType "text/csv"
    ] ;
    dcat:contactPoint [
        a vcard:Organization ;
        vcard:fn "Danish Tax Authority - Data Services"
    ] .
```

**Reusable DCAT Terms for ORP:**
- ✅ `dcat:Dataset` (Layer 1 datasets)
- ✅ `dcat:temporalCoverage`, `dcat:spatialCoverage` (dataset scope)
- ✅ `dcat:keyword`, `dcat:theme` (categorization)
- ✅ `dcat:distribution` (file formats)
- ✅ `dcat:contactPoint` (dataset stewards)

**ORP-Specific Extensions Needed:**
- `orp:exclusionCriterion` (what was excluded and why)
- `orp:syntheticElements` (synthetic data additions)
- `orp:fundingSource` (who funded dataset creation)
- `orp:collectionMethodology` (detailed collection process)

## 3. Dublin Core (DCMI Metadata Terms)

**URL:** https://www.dublincore.org/specifications/dublin-core/dcmi-terms/
**Version:** DCMI Metadata Terms (2020)
**Purpose:** Generic metadata for resources

### Core Terms

| Term | Definition | ORP Use Case |
|------|------------|--------------|
| `dc:title` | Name of resource | **Document title** (Header) |
| `dc:creator` | Entity responsible for creation | **Authors** (Header) |
| `dc:description` | Account of resource | **Summary**, **Dataset descriptions** |
| `dc:created` | Date of creation | **Created date** (Header) |
| `dc:modified` | Date of modification | **Last updated** (Header) |
| `dc:identifier` | Unique identifier | **Document ID** (Header) |
| `dc:subject` | Topic of resource | **Domain** (Header) |
| `dc:rights` | Rights statement | **License** (Header) |
| `dc:publisher` | Entity responsible for availability | **Publishing organization** |
| `dc:contributor` | Entity contributing to resource | **Contributors** (beyond primary authors) |

### ORP Mapping: Document Header

```turtle
:dk-property-tax-reform-2024 a orp:Document, prov:Entity ;
    dc:identifier "dk-property-tax-reform-2024" ;
    dc:title "Danish Property Tax Reform 2024" ;
    dc:description "Analysis of proposed property tax reform..." ;
    dc:creator :asbjorn-ras ;
    dc:created "2024-01-10"^^xsd:date ;
    dc:modified "2024-03-15"^^xsd:date ;
    dc:subject "taxation"@en, "policy analysis"@en ;
    dc:rights <https://creativecommons.org/licenses/by/4.0/> ;
    dc:language "en" ;
    orp:complianceLevel "full" ;
    orp:orpVersion "0.1" .
```

**Reusable Dublin Core Terms for ORP:**
- ✅ `dc:title`, `dc:description`, `dc:identifier`
- ✅ `dc:creator`, `dc:contributor`
- ✅ `dc:created`, `dc:modified`
- ✅ `dc:subject`, `dc:rights`, `dc:language`

**ORP-Specific Extensions Needed:**
- `orp:complianceLevel` (Basic/Standard/Full/PostHoc)
- `orp:orpVersion` (0.1, 0.2, etc.)
- `orp:domain` (policy, ai-training, etc.)
- `orp:status` (draft, final, superseded)

## 4. Schema.org

**URL:** https://schema.org/
**Version:** v28.1 (2024)
**Purpose:** Widely-adopted vocabulary for structured data on the web

### Core Types

| Type | Definition | ORP Use Case |
|------|------------|--------------|
| `schema:Person` | A person | **Author**, **Stakeholder** (Layer 3) |
| `schema:Organization` | An organization | **Funding organization**, **Institutional affiliation** |
| `schema:CreativeWork` | Most generic creative work | **ORP Document** (alternative to prov:Entity) |
| `schema:Dataset` | Body of structured information | **Dataset** (alternative to dcat:Dataset) |
| `schema:Action` | An action performed | **Decision** (alternative to prov:Activity) |

### Key Properties

| Property | Domain | ORP Use Case |
|----------|--------|--------------|
| `schema:author` | CreativeWork | **Document authors** |
| `schema:datePublished` | CreativeWork | **Publication date** |
| `schema:about` | CreativeWork | **Subject matter** |
| `schema:name` | Thing | **Person/organization names** |
| `schema:affiliation` | Person | **Author institutional affiliation** |
| `schema:email` | Person/Organization | **Contact information** |
| `schema:funder` | CreativeWork/Action | **Funding sources** (Layer 1) |

### ORP Mapping: Authors and Affiliations

```turtle
:asbjorn-ras a schema:Person, prov:Agent ;
    schema:name "Asbjørn Ras" ;
    schema:email "asbjorn@example.com" ;
    schema:affiliation :public-reason-project .

:public-reason-project a schema:Organization ;
    schema:name "Public Reason Project" ;
    schema:url <https://publicreasonproject.org> .
```

### ORP Mapping: Stakeholders (Layer 3)

```turtle
:renters-copenhagen a schema:Person, orp:Stakeholder ;
    orp:stakeholderGroup "Renters in Copenhagen" ;
    orp:affectedBy :dk-property-tax-reform-2024 ;
    orp:impactType "indirect" ;
    orp:representation "None" ;  # Absent node
    orp:estimatedPopulation 150000 .
```

**Reusable Schema.org Terms for ORP:**
- ✅ `schema:Person`, `schema:Organization`
- ✅ `schema:author`, `schema:affiliation`
- ✅ `schema:name`, `schema:email`
- ✅ `schema:funder` (dataset funding sources)

**ORP-Specific Extensions Needed:**
- `orp:Stakeholder` (subclass of schema:Person/Organization)
- `orp:stakeholderGroup` (group name/category)
- `orp:representation` (None, Low, Medium, High)
- `orp:impactType` (direct, indirect, externality)
- `orp:estimatedPopulation` (affected population size)

## 6. Reuse vs Custom: Statistical Summary

| Category | Existing Terms | Custom Terms | Reuse % |
|----------|----------------|--------------|---------|
| **Header** | 7/11 | 4/11 | 64% |
| **Layer 1** | 8/14 | 6/14 | 57% |
| **Layer 2** | 1/10 | 9/10 | 10% |
| **Layer 3** | 3/8 | 5/8 | 38% |
| **Layer 4** | 4/8 | 4/8 | 50% |
| **Layer 5** | 5/8 | 3/8 | 63% |
| **Overall** | ~28/59 | ~31/59 | **47%** |

**Interpretation:**
- **High reuse** for metadata (header, Layer 5 forks)
- **Low reuse** for simulation/empathy fields (Layers 2-3)
- **Overall:** Nearly half of ORP terms can use existing ontologies
- **Custom ORP vocabulary** needed for domain-specific provenance and consequence modeling

## 7. Recommended Strategy

### Tier 1: Always Reuse (High Confidence)
- Dublin Core for all document metadata (title, creator, dates, identifier)
- PROV-O for provenance chains (wasGeneratedBy, wasAttributedTo, wasDerivedFrom)
- Schema.org for people and organizations (Person, Organization, name, email, affiliation)
- DCAT for dataset descriptions (Dataset, temporalCoverage, spatialCoverage)

### Tier 2: Reuse with Extensions
- `dcat:Dataset` + custom `orp:exclusionCriterion`, `orp:syntheticElements`
- `prov:Activity` (decisions) + custom `orp:constitutiveLogic`, `orp:rationale`
- `schema:Person` (stakeholders) + custom `orp:representation`, `orp:impact`

### Tier 3: Custom ORP Vocabulary
- All Layer 2 (Consequence Simulation) fields — no good matches
- Layer 3 impact/confidence fields
- Fork-specific metadata (fork_type, key_differences)
- Compliance level, ORP version

### Implementation Priority
1. **Start with Tier 1** (existing terms, maximum interoperability)
2. **Define minimal custom vocabulary** (Tier 2-3)
3. **Version the custom vocabulary** (`https://openreason.org/vocab/v0.1`)
4. **Document mappings clearly** in JSON-LD context
